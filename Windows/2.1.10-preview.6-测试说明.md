# 2.1.10-preview.6 Windows 本地测试版

根据提供的 Gportal 登录页面修复自动填写和登录按钮识别。按钮为 input#first_button，文字是中间带不换行空格的“登 录”，原文字匹配未识别该按钮。

本次修改
只在 /gportal 路径下识别 form#frmLogin 中的 first_name、first_password 和 first_button。按钮必须保留已确认的 login() 点击处理；注册、重置密码、绑定账号表单不参与自动填写。
点击学校原按钮，继续使用学校原 login()、cryptoEncode() 加密和原 AJAX 提交。小助手不重写学校加密、不直接请求认证接口、不改动隐藏的会话参数。
在学校登录脚本、加密依赖或 IV 尚未就绪时等待；未同意协议时暂停提交。观察原登录请求的结果，区分成功、认证拒绝和请求失败，避免重复点击。
沿用 preview.5 的 HTTP 认证页兼容修复及 preview.4 的认证入口探测修复。

安装与测试
先从系统托盘完全退出旧版，再运行安装包；仅关闭窗口不会退出后台程序。
启动后确认页脚为 v2.1.10-preview.6，检查保存的账号和密码，再点击“立即认证”。升级保留原账号配置。学校页面没有运营商或服务选项时，对应设置保持空白。
本包只在本地交付，未推送、未发布；macOS 未修改。原始抓包、用户页面中的会话参数和账号信息不随安装包交付。

验证范围
核心检查 2545 项通过，Gportal 专项 56 项通过；还完成跳转、框架、运营商、协议、验证码和已有学校模板的离线回归。
Gportal 测试使用提供页面中的原 login() 函数、相同控件结构和虚构账号 / 会话参数；加密辅助函数及网络传输使用离线替身，验证原处理函数和加密入口被调用，不构成学校实际 AES 加密或认证成功的证明。
Windows x64 程序和原生测试项目已编译。当前环境为 Mac，未执行 Windows 原生 WebView2 测试；真实校园网自动登录、页面样式及 HTTP 提示是否消失仍需在反馈电脑确认。

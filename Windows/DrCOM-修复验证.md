# Dr.COM 已适配页面的登录循环修复

基于 2.2.3 源码与用户提供的页面结构，修复 Windows 城市热点旧式 Web 登录流程。学校原始 HTML、网关地址、账号和会话未纳入测试夹具。

## 确认的问题

- 登录按钮的 `onclick` 先打开 `:9002/In0`，随后表单 POST。原控制器将所有 HTTP 弹窗改为主窗口导航，可能在学校表单提交时替换原文档；不能用主窗口承接这个状态窗。
- 认证脚本没有识别 Dr.COM 的 `Msg=15` 结果页或带有注销控件的在线状态页。已经在线也可能进入 30 秒校验超时和自动重试。
- 当前源码允许 HTTP/HTTPS 跨主机及跨端口跳转，因此问题不是“所有跨端口都被拦截”。状态窗必须保留独立生命周期。
- 自动发现入口未排除 Dr.COM 状态/注销地址和 hao123 导航页。登录表单等待原本没有截止时间。

## 修改后的行为

- 同主机的 `:9002/In0`、`:9002/0` 使用独立 WebView2，沿用认证浏览器环境及配置目录。保留学校原始 `window.open` 与主表单 POST 顺序。实现依据：[微软 NewWindowRequested 文档](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2newwindowrequestedeventargs)。
- 在线状态需要同时满足 `Logout` 标题、可见的 `javascript:wc()` 注销链接、同主机 `/F.htm` 注销目标、没有密码框。只出现“登录成功”文字或源代码中的成功分支不作为依据。
- `信息返回` 页使用实际执行的 `Msg` 值；15 表示认证成功，14 不表示登录成功，其余非零失败码保留为 `Msg=N`，暂停自动重试供用户查看学校提示。
- 主页面或状态窗确认登录后，停止本次提交与结果超时。自动恢复发起新登录前重查当前 Dr.COM 状态文档，仍明确在线时保留会话；手动“立即认证”可以开启新尝试。
- 目标校园网络确实断开时停止旧认证并释放状态窗；网络重新接通后建立新尝试，不复用断网前的在线文档。
- 关闭状态窗的 X 只隐藏界面，保留浏览器实例；暂停、重置及退出时释放实例。只有用户主动点击学校注销链接才请求 `/F.htm`，并暂停自动认证。
- 入口探测排除已知状态页、注销页、hao123；保留既有锐捷实时入口与跳转逻辑。单个文档等待表单超过 90 秒后结束等待。
- 按钮文字去掉空白后匹配，兼容 `登　录`；同名 reset 控件仍排除。

## 联网状态的处理边界

保留“HTTP 明确要求认证时优先于 ping”的现有规则。既有 SRun 回归已经覆盖未认证网络允许 ICMP 的情况，不能全局回退为只看 ping。若学校在线状态与外网探测仍不一致，显示学校已登录但继续检查实际联网，不通过重复 POST 解决。

当前文档仍显示在线，并不证明网关会话永不过期；本次通过重读文档阻止重复提交，不主动刷新状态窗，以免触发学校 `onUnload` 的新窗口/会话行为。遇到实际断网可手动重新认证。真实外网访问、网关计费及会话持续性仍需学校网络验证。

## 验证

- 本地 Windows x64 应用及原生测试项目交叉编译通过，零警告、零错误。
- 本地核心检查 2826 项通过，包括状态窗地址约束、入口排除和错误码处理。
- 离线 Chromium 专项通过：独立弹窗及真实表单 POST、重复 ID/reset、全角空格按钮、成功/失败/注销结果、状态页不再提交及反例。
- Windows 原生 WebView2 测试已加入 CI，覆盖主表单提交、跨端口状态窗、自动重试复用、关闭隐藏、直接调用学校 `ee()` 替换函数与清理。现代 Chromium 可能抑制实际卸载事件中的 `window.open`，因此不把该测试写成“实际 onUnload 弹窗已通过”。具体运行结果以本次修复提交的 Actions 记录为准。
- 尚未在学校真实网络认证，不能将离线夹具或 CI 通过等同于现场网络修复已确认。

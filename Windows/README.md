## 本地模型、zPortal 与自动检测调整 2.0.3-local.8

- 随包提供 ddddocr 1.5.6 默认非 beta 验证码模型（MIT，约13.6 MB），通过 ONNX Runtime 1.23.2 CPU 推理；无需 Python。模型和字典固定 SHA-256，来源与适配说明随文件提供。
- 按比例缩放到64像素高，灰度及色彩分离两种输入；在全部字符类别中解码，再拒绝非数字，不将字母猜成数字。重复数字按 CTC 空白分隔规则保留；分数不足或处理结果冲突时保留人工输入。
- 模型优先、Windows 系统 OCR 后备；突出显示结果来源，沿用复制、粘贴、原图核对与人工确认。模型首次加载不依赖 Windows OCR 语言包。模型预算6秒，整体窗口仍受12秒取消限制；识别串行执行，避免重复窗口积累推理任务。
- 模型和原生推理库随安装包提供。缺少 Visual C++ 运行库时，安装器仅从微软下载，确认签名有效且发布者为 Microsoft 后调用官方安装器；可能需要联网和管理员授权。补全失败时保留手动输入和可用的系统 OCR，重启程序后可重试模型。
- 依据用户提供的脱敏结构适配 zPortal：`#tx` 提示框切换到隐藏的 `#password`，选择 `#login_submit`，不误点二维码按钮；验证码提示文字不视为已输入。通过特定结果页结构识别学校认证完成，联网仍以 ping 为准。
- 关闭自动连接会停止定时器；自动连接开启且 ping 通时改为20秒联网探测，不再每秒扫描 Wi-Fi；确认掉线后恢复1秒网络检测。手动刷新和连接保留，按钮防闪烁逻辑继续生效。
- 本轮仅编译、打包和静态文件检查；没有执行模型推理或浏览器/原生测试，尚不能量化准确率提升。

- 每 1 秒检查目标 Wi-Fi，首次满足条件立即连接，Wi-Fi 失败后最早 1 秒重试，不再等待 60 秒。

## 2.0 正式版（2.0.0）：连接方式、自动勾选与反馈入口

Windows 界面左下角提供「如果遇到问题请点击：!」入口。使用中如遇到问题，请点击感叹号查看联系方式并联系作者。

Windows 与 macOS 同步提供 2.0.0 正式版，平台认证方式的差异见更新说明。

[更新说明](2.0-更新说明.md)

在「校园网设置」明确选择 **Wi-Fi 无线网络** 或 **有线网络（以太网）**。旧配置的 Wi-Fi 名称留空仍映射为有线模式。修改后需保存才会用于实际连接；窗口标题、网络概览图标和认证页提示使用当前已保存的方式。侧栏统一显示「校园网络」。

有线模式提供以下认证方式：

| 方式 | 使用前的配置 | 点击立即连接后的行为 |
| --- | --- | --- |
| 网页认证 | 填写学校认证地址、上网账号密码；服务选项没有时留空 | 打开学校网页、填写并按设置提交 |
| PPPoE 宽带拨号 | 先在 Windows 创建 PPPoE 宽带连接并保存凭据，选择对应宽带连接名称 | 调用 Windows 拨号，复用该系统连接保存的凭据及网卡配置 |
| 802.1X 系统认证 | 按学校要求配置以太网属性、EAP/证书和凭据，启用 Wired AutoConfig；可指定以太网接口 | 向所选接口发起重新认证；系统要求权限时需处理权限提示 |
| 学校专用客户端 | 选择已安装的学校认证客户端 EXE | 启动客户端，已运行时不重复启动；客户端内登录与私有协议由该客户端处理 |

这些方式都不需要 Wi-Fi 名称。拨号和 802.1X 之前的物理以太网检测不再要求已有 IP 地址；网页认证、802.1X 与客户端模式中，指定以太网接口不存在或网线断开时不会改选其他以太网接口；PPPoE 的实际网卡由所选 Windows 宽带配置决定。开启自动连接后按间隔重试，暂停后停止新的尝试。

网页认证新增必选勾选项处理：自动勾选登录表单中可识别的必选框、同意协议项，并调用网页原有点击事件。已选项不重复操作；记住密码、自动登录、推广订阅等选项保留原状。异步勾选稍作等待；勾选被网页拒绝或需要人工阅读确认时暂停提交并提示处理。原有认证网址、当前网络校验和提交去重继续生效。

实现依据：[Microsoft rasdial 文档](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2012-r2-and-2012/ff859533%28v%3Dws.11%29)、[Microsoft PPPoE 文档](https://learn.microsoft.com/en-us/windows/win32/rras/point-to-point-protocol-over-ethernet-connections)、[Microsoft netsh lan 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-lan)。此功能复用系统中已配置的连接与学校客户端，不生成或猜测学校 EAP/证书配置。

实际 PPPoE 拨号、802.1X、学校客户端及校园网页协议勾选需在相应 Windows 和学校网络验收。Windows 浏览器和 ping 继续使用系统路由；有多个网络或 VPN 时需确认学校地址可达。

## 构建

安装 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)，在仓库根目录执行：

```powershell
dotnet run --project Windows/tests -c Release
powershell -ExecutionPolicy Bypass -File Windows/build.ps1 -Runtime win-x64
```

输出位于 `Windows/dist/win-x64/`，包含 `CampusConnect.exe`、原生运行库及模型文件。

生成安装程序还需要 [NSIS](https://nsis.sourceforge.io/Download) 和 Python 3。在 PowerShell 执行：

```powershell
powershell -ExecutionPolicy Bypass -File Windows/build-installer.ps1 -Runtime win-x64
```

构建时从 Microsoft 下载并验证 WebView2 引导程序签名，输出 `Windows/installer/dist/CampusConnect-Windows-x64-Setup.exe`。

已发布程序的情况下，可通过 Python 调用原生 NSIS 编译器跨平台构建安装包：

```sh
python3 Windows/installer/build.py --makensis /path/to/makensis --bootstrapper /path/to/MicrosoftEdgeWebview2Setup.exe
```

安装器默认交互运行，也支持 `Setup.exe /S /D=D:\Apps\CampusConnect` 静默安装，`/D=` 必须放在最后且不加引号；`/SKIPWEBVIEW2` 仅用于已另行部署 WebView2 的环境，缺少该组件时程序无法显示界面。静默卸载默认保留用户配置。

macOS / Linux 安装 .NET 10 SDK 后也可交叉编译 Windows 运行包：

```sh
dotnet publish Windows/source/CampusConnect.csproj -c Release -r win-x64 --self-contained true -p:PublishReadyToRun=true -o Windows/dist/win-x64
```

此应用和安装器未进行 Windows 商业代码签名。安装包已完成交叉编译与打包检查，但安装向导、快捷方式、卸载以及校园连接仍需在 Windows 实机验证；见仓库根目录的 `VALIDATION.md`。

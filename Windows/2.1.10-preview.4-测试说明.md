# 2.1.10-preview.4 Windows 本地测试版

本次针对抓包中“Ping 通，但网页登录仍未完成，助手没有自动填写”的情况修复。

修复内容
1. 网页认证模式保留百度 Ping 检查，同时读取不自动跟随跳转的 HTTP 联网探测结果。明确收到认证跳转、登录页替换或 HTTP 511 时，继续按未完成认证处理，避免提前清空本次密码并结束自动填写。
2. 按当前网络返回的真实认证入口继续在应用内打开页面、跟随跳转、填写和点击学校原有登录按钮。临时入口只用于本次尝试，不修改已保存账号、密码、Wi-Fi 名称和认证地址。
3. 探测有时限，未知的 HTTP 探测故障本身不会把成功 Ping 判为断网。点击停止、暂停或切换配置后，尚未返回的入口探测不会重新拉起旧登录。
4. 沿用 preview.3 的“立即登录”按钮识别、联网后关闭旧向导、具体加载错误码等修复。

使用
退出系统托盘中的旧版，运行安装包，确认页脚为 v2.1.10-preview.4。
保留原配置。确认保存的目标 Wi-Fi 与当前学校网络一致，账号密码已保存；开启自动连接和自动提交后测试应用内跳转、自动填写和登录。手动提交模式仍只填写。
当前网页没有运营商 / 服务选择框时，对应设置留空。
新包只在本机交付，未推送源码、未上传安装包、未发布 GitHub Release，macOS 未修改。

抓包依据
21:31:39 与 21:32:09，HTTP 连通性请求返回 307，指向当前网络认证服务器。
认证页经 302 到达 /srun_portal_pc，返回 HTTP 200；/cgi-bin/rad_user_info 明确返回 not_online_error。
同一抓包期间，对百度解析地址的 7 次 ICMP Echo 都收到回复。因此单独 Ping 成功不能代表该校园网络已经认证。
本次抓包对应深澜门户，与此前截图中的电信入口不同；新版使用当前网络检测到的入口，不硬编码学校 IP。
